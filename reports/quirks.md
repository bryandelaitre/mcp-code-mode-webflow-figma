# Écarts entre les schémas et le comportement réel

Serveur testé : `webflow-mcp-server` 1.0.0 (npm, stdio). Les écarts relevés sur le MCP hébergé pendant les projets
clients sont dans `WEBFLOW_MCP_LESSONS.md` (projet Client E) ; ceux-ci concernent le serveur local.

| Date | Outil | Schéma / attente | Comportement réel | Contournement |
|---|---|---|---|---|
| 2026-11-24 | démarrage | `tools/list` ne fait aucun appel API | Le processus s'arrête (`Error: WEBFLOW_TOKEN is missing`) si `WEBFLOW_TOKEN` est vide, même pour lister les outils | `dump-schemas` passe une valeur factice (`schema-dump-only`) quand aucun token n'est fourni |
| 2026-11-24 | tous les schémas | sous-schémas autonomes | 42 `$ref` relatifs à la racine de l'outil (`#/properties/actions/items/...`) : un sous-schéma extrait seul ne se résout plus | `codegen` résout les `$ref` avant de découper par action |
| 2026-11-24 | outils multi-actions (`style_tool`, `element_tool`, `variable_tool`…) | « une action par item » (description) | Le schéma décrit un objet aux propriétés toutes facultatives, sans `oneOf` : rien n'empêche zéro ou plusieurs actions dans un item | Le type généré est une union « exactement une clé » |
| 2026-11-24 | `element_builder` | même forme que les outils multi-actions | Ses items sont des constructions (`parent_element_id`, `creation_position`, `element_schema` obligatoires), pas des actions | `codegen` ne traite en multi-actions que les items sans champ obligatoire |
| 2026-11-24 | jeu d'outils | même surface que le MCP hébergé (`data_*`) | Noms et découpage différents (`collections_items_list_items` au lieu de `data_cms_tool`, pas de `data_whtml_builder`, pas de props de composants) ; édition d'éléments, styles, variables et assets réservée aux outils Designer | V1 limitée à la Data API (CMS, pages, SEO, publication, scripts) |
| 2026-11-24 | `collections_items_publish_items` | publie les items passés en `itemIds` | `HTTP 409 Conflict : The site is not published` tant que le site n'a jamais été publié ; les items sont déjà écrits à ce stade | `upsertCmsItems` renvoie `publishError` au lieu de lever une erreur ; publier le site une fois (`publish()`) puis relancer |
| 2026-11-24 | MCP hébergé (`mcp.webflow.com`, v2.2.0) | accessible seulement depuis Claude Code | OAuth standard (enregistrement dynamique, PKCE, `refresh_token`, accès 1 h) : utilisable depuis un script ; 38 outils, `session_id` / `agent_id` / `context` obligatoires ; ses `actions` sont des `anyOf` stricts (`label` + une action obligatoires), contrairement au serveur local | `src/lib/hosted.ts` + `npm run hosted-login` ; jetons dans `.cache/` (600, non versionné) |
| 2026-11-24 | `data_element_tool` · `query_elements` (hébergé) | renvoie les éléments filtrés | Sur la page Style Guide du bac à sable (`element_filter: {type: "Heading"}`, `children_depth: 1`) : `status: "error"`, « Element does not have a configurable visibility setting », aucun résultat | `findElements` filtre un seul `get_all_elements` dans le script, sans `query_elements` |
| 2026-11-24 | outils du MCP hébergé | un échec rend `isError` | Une action en échec (404, 429, `status: "error"` des outils éléments) arrive dans son résultat (`error` ou `[{status, message, data}]`) avec `isError: false` | `hostedResult()` lève une erreur d'une ligne par action ; `callHosted` ne rejoue un 429 que si toutes les actions du lot sont en 429 (aucune écriture rejouée) |
| 2026-11-24 | MCP hébergé, limite de débit | — | `Too Many Requests` après une rafale (~100 appels en quelques minutes pendant le benchmark) | Nouvel essai automatique (5 s, 10 s, 20 s, 40 s, 60 s) |
| 2026-11-24 | `data_cms_tool` · `create_collection_items` (hébergé) | même défaut que l'API v2 | `isDraft` vaut `true` par défaut (documenté dans le schéma), contre `false` sur le serveur local | `api.itemsCreate` passe `isDraft: false` pour garder le même comportement sur les deux serveurs |
| 2026-11-24 | `data_component_props_tool` · `get_component_instance_props` | props et types | Renvoie nom, id et valeur, sans le type ; les props `variant` d'un composant qui pilotent un composant imbriqué ne listent pas leurs variantes (`includeVariants` ne renvoie que `base`) | Types lus par `get_component` (`includeProps`) ; une prop `variant` prend l'id de variante en chaîne |
| 2026-11-24 | `data_assets_tool` · `create_asset` (hébergé) | crée un nouvel asset | Déduplication par MD5 : un fichier identique déjà présent renvoie l'asset existant (même id, même après suppression) **et le renomme avec `file_name`**. Un test a ainsi supprimé puis restauré `chatgpt-icon.avif` du bac à sable | `uploadAssets` repère l'id existant, remet le nom d'origine, ne touche pas à l'alt et marque `preexisting: true` ; ne jamais supprimer un asset renvoyé avec `preexisting` |
| 2026-11-24 | `create_asset` · `uploadDetails` | champs du formulaire S3 | Clés en camelCase (`xAmzAlgorithm`, `policy`, `successActionStatus`…) ; envoyées telles quelles, S3 répond 403 | `s3Fields()` les renomme (`X-Amz-Algorithm`, `Policy`, `success_action_status`…) |
| 2026-11-24 | `list_assets` | taille de l'asset | `size: 0` pour un asset envoyé par S3 ; `hostedUrl` au format S3 (celui que le WHTML relie), alors que `create_asset` renvoie une URL `cdn.prod…` | Doublons comparés par nom (taille ignorée si 0) ; la lib renvoie toujours l'URL S3 |
| 2026-11-24 | `asset_tool` · `upload_image_by_url` | outil hébergé utilisable seul | « Unable to connect to Webflow Designer » : exige le Designer ouvert avec l'app MCP | `uploadAssets` télécharge l'URL dans le script puis passe par `create_asset` + S3 |
| 2026-11-24 | `data_element_settings_tool` · `get_settings` `query_settings` | `queries: [{key: "attributes"}]` renvoie les attributs | 0 résultat alors que `all_raw_settings` renvoie `attributes: [{name: "theme", value: "dark"}]` | `readSettings` lit en `all_raw_settings` et filtre dans le script |
| 2026-11-24 | `set_settings` · `domId` | `static_text: {value: ""}` vide l'id | Refusé ; `clear: true` fonctionne | `""` et `null` deviennent `clear` |
| 2026-11-24 | `set_settings` · `domId` | écriture d'un id | Après un premier `domId` posé puis effacé, toute nouvelle valeur sur le même élément échoue : « MPS rejected update … [Conflict] The operation could not be applied to the component map » (`BATCH_FAILED`), les autres clés du lot étant appliquées | `setSettings` relit après écriture et liste `notApplied` ; poser l'id dans le Designer si le conflit persiste |
| 2026-11-24 | `data_style_tool` · `query_styles` | `name_path: ["x"]` trouve la classe x | Correspondance par sous-chaîne (`["button"]` renvoie `navbar_button-group`, `filter-ui_button`…) ; breakpoints rangés dans `properties.breakpoints.<bp>.properties`, variables sous la forme `{id: "variable-…"}` | `ensureStyles` filtre sur le nom exact (et le sélecteur pour un combo) et lit `properties.breakpoints` |
| 2026-11-24 | `data_whtml_builder` · classes | toutes les classes du HTML sont créées | Seules les classes qui ont une règle dans `css` sont créées et posées ; les autres disparaissent sans avertissement (une règle vide `.x {}` suffit). Une classe qui existe déjà sur le site est posée sans règle | `insertSection` ajoute `.x {}` pour les classes nouvelles sans règle (vérifiées par `query_styles`) et relit la page pour lister `lostClasses` |
| 2026-11-24 | `data_variable_tool` · modes | renommer ou supprimer un mode | Aucune action pour renommer ni supprimer un mode (seulement `create_variable_mode`) | À faire dans le Designer ; la lib le liste en fin d'intégration |
| 2026-11-24 | `data_fonts_tool` · `create_font` | renvoie l'id de la police | L'id n'est pas au premier niveau de la réponse (l'envoi fonctionne) | `uploadFonts` relit `list_fonts` après envoi |
| 2026-11-24 | `create_*_variable` (couleur) | `static_value` hexadécimal | `rgba(242, 236, 233, 0.08)` accepté tel quel en `static_value` | — |
| 2026-11-24 | `data_scripts_tool` · `add_site_script` | applique un script enregistré | Sur un site sans script appliqué : 404 « Custom code block not found », **renvoyé dans `result`** (pas dans `error`) ; `get_site_scripts` répond aussi 404 | `set_site_scripts` (liste complète) crée le bloc ; `hostedResult` lève désormais sur un `result` de la forme `{name: "Error", …}` |
| 2026-11-24 | `data_element_builder` · `set_style` | applique la classe ou signale l'erreur | Classe absente du site : élément créé **sans classe et sans erreur** (`code-css` absente du gabarit de ce site) | `buildElements` et `setClasses` créent d'abord les classes de base manquantes |
| 2026-11-24 | `data_whtml_builder` · liens | crée un lien Webflow | Le lien est créé avec son réglage **et** un attribut personnalisé `href` en double | `fixLinkAttributes` (automatique dans `insertSection`) pose le réglage et retire l'attribut |
| 2026-11-25 | MCP Figma distant · enregistrement dynamique (`/v1/oauth/mcp/register`) | client enregistré (le serveur annonce `registration_endpoint`) | `403 Forbidden` pour un client hors liste blanche | serveur local de l'application Figma (`127.0.0.1:3845/mcp`), sans autorisation |
| 2026-11-25 | MCP Figma local · `get_metadata` / `get_design_context` sur un cadre de page (1440×10 416) | arbre de la page | le cadre seul, **sans enfants** (600 car.) | sections passées une par une ; liste des enfants par `use_figma` |
| 2026-11-25 | MCP Figma local · `get_design_context` sur une section avec motif vectoriel (13 428 vecteurs) | code de référence | renvoie les métadonnées XML à la place du code (1,3 M car.) | `figmaSpec` replie les sous-arbres graphiques et lit les autres enfants un par un |
